1. 現況一句話

這個專案從原本的「單檔、多執行緒 NVMe 壓力測試工具」演化成 模組化的儲存資料完整性測試框架，新增了一條 單執行緒 io_uring + O_DIRECT 的 power-cycle(斷電完整性)測試路線， 可同時涵蓋 NVMe / SATA / USB。每個 sector 都帶 32-byte 完整性 tag,讀回逐欄驗證。

✅ 已完成

模組化重構、CLI/config、io_uring 引擎、range×access、journal、pcwrite/pcscan 編排、嚴格 PLP completion-level 追蹤。66 個單元測試全過。

🔬 已驗證

檔案層級 PASS/FAIL、真實 /dev/sda USB 上 io_uring+O_DIRECT、模擬斷電多 cycle、PLP 退版偵測。

⚠️ 限制

目前的模擬斷電不切 VBUS(測不到真 cache 遺失);真 ungraceful 需接實體切電 hook。

2. 三種模式

模式指令何時用
壓力測試DiskIOStress [opts] <dev>多執行緒持續 write/read/compare 轟一顆裝置(原工具)
單一指令DiskIOStress <dev> <subcmd>一次性 NVMe 操作:read/write/trim、SMART、韌體、reset
Power-cycleDiskIOStress <dev> pcwrite …反覆斷電下的資料完整性(graceful+ungraceful、PLP 驗證)
⚠️ 所有模式都直接寫 raw block device,會毀掉裝置上所有資料。 破壞性操作前會先列乾淨的裝置清單(實體碟 + model + 掛載點,排除 loop)並要求確認;若目標掛載著系統(/ 或 /boot)會擋下來、要打出完整裝置路徑才放行,避免誤刪系統碟。

4. Sector Tag(三種模式共用核心)

每個 sector 開頭埋 32-byte 結構化 tag,pattern 只填後面。讀回逐欄檢查,錯誤被精確分類而非籠統的 compare error。

欄位抓什麼
magicsector 沒被寫過 / torn write(半寫)
lbamisdirected IO(資料跑到錯位址)
seed上一次 run 的殘留資料
write_loop(generation)stale data:LBA 對但世代是舊的
thread_id / trunk_indexcross-thread / cross-region 汙染
pattern / workloadrun-level metadata 一致性
payload_crc(CRC32)sector body bit-rot
power-cycle 模式把 write_loop 當作 generation counter 使用 —— 這是斷電後判定「哪些資料該存活」的關鍵。

5. 模式 1：壓力測試

sudo ./build/DiskIOStress /dev/sdb
sudo ./build/DiskIOStress --qd=64 --io-size=128K --pattern=addr --ranges=0-4G /dev/nvme0n1

單執行緒 io_uring + O_DIRECT(block 層,通吃 NVMe/SATA/USB)。並發來自 io_uring 的 queue depth(--qd),不再開多執行緒。Pattern 多 12 種含新的 addr(自我描述,好 debug)。Workload 用 --workload= 指定,見下表。

--threads / --trunk-size 仍可接受但已忽略(並發改由 --qd 控制)。改 block 層後壓測模式不再測 NVMe stream write-hint。

5.1 Workload 差異

分兩大類:相位分離(整段全寫 → 整段全讀回比對,讀寫不重疊)與併發(讀寫同時進行)。

Workload類型順序每一輪做什麼
seq-verify相位分離順序整段寫 → 整段讀回驗證
rand-verify 預設相位分離亂序同 seq-verify,但拜訪順序打散(全覆蓋)
seq-verify-2x相位分離順序寫一次 → 整段讀回驗證兩次(抓 read-disturb / 不穩定讀)
retention相位分離順序只在第一輪寫,之後每輪只重讀驗證(保存力 / bit-rot)
concurrent-rw 新併發亂序先 pre-seed 一次,然後同時讀+寫,比例由 --rw-ratio 控制
  • seq-verify:最基本。第 N 輪用 generation-N 的 tag 整段寫入,再整段讀回逐 sector 比對;下一輪改 N+1。靠 generation 計數抓「停留在舊版本」的 stale 資料。
  • rand-verify(預設):跟 seq-verify 一樣每輪寫滿整段,只是順序被打散 —— Feistel 全覆蓋排列,每個 sector 剛好一次(不漏不重),但跳著走而非 0,1,2…。順序是 (位置, generation, seed) 的純函數(無 rand()),同 seed 完美重播,每輪換一套確定順序。用來操 FTL / mapping table。
  • seq-verify-2x:同 seq-verify 但每輪讀回兩次。第二次讀抓「讀一次對、重複讀就錯」的 cell(read-disturb、邊界 cell)。
  • retention:整段只寫一次(第一輪),之後每輪只重讀驗證、不重寫。配 --test-time 回答「寫進去的資料過幾小時/幾天還讀得對嗎」(資料保存力)。
  • concurrent-rw:唯一讀寫同時的 workload。先 pre-seed 整段(讓讀一定打到有效資料),再在同一條 queue 上同時丟讀和寫。--rw-ratio=N 設讀的百分比(預設 70)。讀用 scrub 驗證(magic/LBA/CRC,任何 generation 都算對),所以併發中被蓋寫不會誤判,只有 torn write / bit-rot / misdirection 才 fail;讀和寫不會同時打同一 LBA(O_DIRECT 重疊無原子性保證)。op 類型與位置都 seed-deterministic,可重現。測「讀寫競爭下」的完整性 —— 相位分離 workload 做不到。沒有自然的「一輪」結束點,用 --test-time 限時。
舊名 seq_wrc / rand_wrc / seq_wrrc / seq_w1rcn / mix_rw 仍可當 alias 使用。

6. 模式 2：單一指令

sudo ./build/DiskIOStress <dev> <subcmd> [args…]   # 數值參數為 16 進位

w/r/t(單筆寫/讀/trim)、sw/sr(循序吞吐)、rw/rr(隨機吞吐)走 io_uring,通吃所有 transport(t 用通用 BLKDISCARD);rst(reset)、log(SMART=0x02)、fwact(韌體)為 NVMe 專屬。

7. 模式 3：Power-cycle 測試 重點

sudo ./build/DiskIOStress /dev/sdb pcwrite \
     --ranges=0-1G --access=random --io-size=64K --qd=32 \
     --durability=plp --checkpoint-interval=1M \
     --cut-after=64M --graceful-ratio=0.5 --cycles=100 \
     --power-hook=./power-hook.example.sh
# 或把整組設定寫進 INI:
sudo ./build/DiskIOStress /dev/sdb pcwrite --config=powercycle.conf.example
跟模式 1 的 workload 是兩件事。 共用 sector tag 與 io_uring 引擎,但問的問題不同 —— workload 測「正常讀寫資料對不對」,power-cycle 測「斷電後 host 認定已落地的資料還在不在」。graceful/ungraceful 不是 workload,是這個模式的兩種關機方式;這裡不看 --workload,存取樣式改用 --access=seq|random。
壓測 workload(模式 1)Power-cycle(模式 3)
指令DiskIOStress <dev> [opts]DiskIOStress <dev> pcwrite …
測什麼正常操作下資料正確性斷電後 durable 資料是否存活
失敗領域一般完整性crash consistency(flush/FUA、PLP、torn write)
存取樣式--workload=--access=seq|random(忽略 --workload)
需要裝置即可切電 hook(或 --power-hook-dry-run)

7.1 一個 cycle 的流程

寫帶 tag 的資料 (QD 深) │ (依 ranges × access 走 unit,每寫一輪 generation +1) ▼ 呼叫 power-hook cut-graceful / cut-ungraceful ← 你的斷電腳本 ▼ 呼叫 power-hook restore → 等 /dev/... 回來 ▼ pcscan 讀回全範圍 → 逐 unit 分類 → PASS / FAIL ▼ loop(下一個 cycle)

7.2 斷電的 trigger:何時斷、斷哪種

兩個獨立的旋鈕:

旋鈕控制行為
--cut-after
(預設 64M,下限)
--cut-jitter
(預設 0)		何時斷每個 cycle 斷點 = cut_after + rand(0..jitter),不會低於 cut_after(不會太短),random 取自 seeded RNG → 同 seed 重播。兩者各自可填 size(64M)或時間(30s;小寫 m=分鐘、大寫 M=MB)。兩段式:先到 cut_after floor,再多跑 0..cut_jitter,各用自己的單位 —— 例 --cut-after=30s --cut-jitter=256M = 「寫滿30秒,再多寫隨機0–256MB才斷」。純 size+size 為 byte-identical 可重播;含時間則 byte 數逐次略變(判定仍正確)。每 cycle 實際寫入量印在 log:--- cycle 3 (graceful, wrote ~187MB) ---。
--graceful-ratio=<0..1>
(預設 0.5)		斷哪種每個 cycle 開頭用 seeded RNG 擲一次:graceful = rand() < ratio。0.5 ≈ 一半 graceful 一半 ungraceful,隨機交錯但因 seed 固定可重播;0=全 ungraceful、1=全 graceful。
  • graceful:寫滿 cut-after → drain + flush + 把 durable 推到 submitted → 在沒有 in-flight IO 的靜止點斷。at-risk window 空 → 所有資料都必須存活(acceptable=0)。模擬正常關機。
  • ungraceful:一個 cutter thread 在主執行緒還在持續灌 IO 時、submitted byte 一達 cut-after 就立刻觸發斷電 hook,電源在 ~qd 筆寫入真正 in-flight 時掉下去(真·IO 中斷電)。at-risk window [durable, submitted) 的 in-flight 遺失算 acceptable,但 [0, durable) 掉了就是 stale=FAIL。模擬突然拔電。
可重現性:trigger(cut-after)與「哪種」(seeded graceful-ratio)都是確定的,at-risk 區間在發 IO 前 就寫進 journal,所以判定可完全重播。唯一不可控的是 relay 打開那一瞬間 controller 正在 program 哪個 sector(物理層)。

7.3 generation + journal 判定模型

一個 pass 把 range 內每個 unit 恰好重寫一次(循序,或 Feistel 全覆蓋隨機),然後 generation 進位 —— 所以同一區同時最多只有兩個世代(G 與 G-1)。host 端 journal(atomic 寫、放在受測碟之外,才能撐過斷電)記錄世代與 pass 的 durable 進度:

pos < durable_units → 必須是世代 G (已 durable,必須存活) durable_units ≤ pos < submitted → at-risk 窗口 (G 或 G-1 都可接受) pos ≥ submitted → 這輪還沒寫到 (應為 G-1)

斷電重開後 pcscan 把每個 unit 歸類為:newest(G) prev(G-1) acceptable(at-risk 內的 in-flight 遺失) stale(durable 資料遺失=失敗) corrupt(magic/CRC/LBA=半寫或損壞)。PASS ⟺ stale==0 且 corrupt==0。

8. Durability:volatile vs PLP

volatile(一般 SSD)plp(電容保護 SSD)
durable 定義已 flush已 complete(caps 保證落地)
durable 推進flush 完成時(--flush-interval 粒度)每個 io_uring completion 前綴,每 --checkpoint-interval 持久化
可接受遺失窗口上次 flush 之後的所有寫入只剩斷電當下真正 in-flight(≈ QD)
已完成寫入遺失可能落在 at-risk → 被吞落在 durable → 判 FAIL
checkpoint 單位--checkpoint-interval(plp)與 --flush-interval(volatile)皆為 bytes,可加 K/M/G/T(1024 進位),預設 1M。意義:已完成資料每累積這麼多 bytes,就把 durable 點寫進 journal 一次 —— 越小越嚴格,代價是更多 journal fsync。
PLP 模式是一個斷言:你宣告「這是 PLP 碟」,測試就驗證「每個已完成的寫入都存活」。已驗證:把一個 durable 區的 unit 退回前一世代 → FAIL;同一份資料若落在 at-risk 窗口 → PASS。completion-level 邊界正是嚴格性的來源。

9. Power-control plugin

pcwrite 在每個電源事件呼叫你的外部腳本,介面是位置參數 + 環境變數混合:

power-hook.sh <verb> <device>     # verb = cut-graceful | cut-ungraceful | restore
   env: DIOS_GENERATION DIOS_CYCLE DIOS_PHASE DIOS_TIMEOUT DIOS_DRY_RUN
   exit 0 = 成功,非 0 = 中止測試
  • power-hook.example.sh — 範例模板(uhubctl / GPIO 繼電器 / 網路 PDU / rtcwake 範例)
  • power-hook.usb-sim.sh — 用 sysfs authorized 開關模擬 USB 斷線(不切 VBUS)
真 ungraceful 要硬體切 VBUS。 sysfs 模擬只是邏輯斷線,drive cache 不會真的掉電,足以跑通 disappear→reappear→rescan 迴圈,但證不了真實 ungraceful / PLP 行為。
